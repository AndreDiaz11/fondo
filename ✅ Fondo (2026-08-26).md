# Fondo

## Qué es
App personal para Android que funciona como un monedero virtual sin conexión — registra saldo, depósitos y retiros con motivo, fecha y hora, y lleva historial completo. Uso personal (y de un grupo chico de personas conocidas), sin cuentas, sin internet, sin backend: todo vive en el dispositivo.

## Cómo se ve y funciona
El usuario abre la app y ve el saldo de la cuenta activa en grande, con resumen del mes (ingresos, gastos, balance). Puede tener varias cuentas (efectivo, banco, viaje, etc.) y cambiar entre ellas con un selector, además de renombrarlas. Para agregar dinero o gasto escribe el monto y el motivo — no se puede retirar más de lo que hay (nunca queda en negativo). El historial muestra los últimos 3 movimientos, con "Ver todo" abriendo el historial completo; cada movimiento se puede editar o eliminar (menos el "saldo inicial", que solo se establece una vez por cuenta). Hay filtros por tipo/mes/texto, y modo claro/oscuro.

Los datos se pueden **exportar** (JSON para respaldo completo, o CSV para Excel) — el botón abre directo el diálogo nativo "Guardar como" de Android, el usuario elige la carpeta del celular donde guardarlo, sin pasar por WhatsApp/Gmail/Drive como intermediario. **Importar** lee ese mismo JSON y reemplaza los datos del dispositivo (con confirmación previa mostrando cuántas cuentas/movimientos trae).

**Primera apertura sin datos**: si la app no encuentra nada guardado localmente, muestra una pantalla de bienvenida que guía a traer el respaldo de la versión anterior (exportar de la vieja → importar en la nueva) — este fue el mecanismo real usado para migrar el saldo/historial de producción sin perder nada, ya verificado con datos reales.

## Stack
- **React Native 0.81.4** (TypeScript, New Architecture) — reemplaza Capacitor (HTML/CSS/JS + WebView). Solo Android.
- **Zustand + AsyncStorage** — mismo esquema de datos exacto que el `localStorage` original (`fondoData`), incluida la migración automática de la clave legacy (`controlDineroData`).
- **@react-native-documents/picker** — selector de archivos para importar, y diálogo nativo "Guardar como" para exportar directo al dispositivo.
- **@react-native-picker/picker** — selector de cuenta activa y de filtro.
- Sin backend, sin base de datos remota, sin claves de API — 100% local.

## Decisiones (excepciones justificadas)
1. **Mismo `applicationId`** (`com.personal.controldinero`) que la versión Capacitor — pero **firma nueva**: la llave original de la app anterior (debug estándar, según su propia documentación) no se pudo recuperar/igualar en esta máquina. Quien tenga la versión vieja instalada debe desinstalarla antes de instalar esta — confirmado y aceptado por el usuario, sin pérdida de datos (verificado con el flujo de exportar/importar).
2. **Repo público** (no privado, la config por defecto de la skill) — el chequeo de actualizaciones usa la API pública de GitHub Releases sin autenticación; un repo privado la bloquea (404), que fue justamente el primer bug encontrado al probar el auto-actualizador. No hay ningún dato ni secreto en el código — el saldo/historial del usuario nunca toca el repo, vive 100% local en cada dispositivo.
3. **Sin monitoreo de errores en producción / sin revisión diaria automática** (reglas 19 y 22 de la skill) — no aplican, no hay backend ni base de datos que monitorear.

## Archivos clave
- `src/lib/estado.ts`: toda la lógica pura de negocio (crear cuenta, recalcular saldo, normalizar un respaldo importado) — sin dependencias de React, fácil de verificar.
- `src/store/fondoStore.ts`: única fuente de verdad del estado, persiste a AsyncStorage en cada cambio, mismo esquema exacto que la versión anterior.
- `src/lib/respaldo.ts`: exportar (JSON/CSV, guarda directo al dispositivo vía Storage Access Framework) e importar (con previa de cuántas cuentas/movimientos antes de confirmar).
- `android/app/build.gradle`: `versionName` se deriva de `package.json` (fuente única) — evita que el chequeo de actualizaciones quede desincronizado del build real.

## Instalar y correr
Dentro de `project/`:
```
npm install
npx react-native run-android
```

## Env vars
No requiere — sin backend.

## Auto-actualización
Sí, vía GitHub Releases — repo: `AndreDiaz11/fondo` (público). El APK se descarga e instala directo desde la app (`services/apkInstaller.ts`, permiso `REQUEST_INSTALL_PACKAGES`). Verificado de punta a punta en producción: detecta, descarga e instala solo, sin intervención manual.

**CI optimizado desde el día uno**: cache de Gradle/npm + workflow de precalentamiento en `main`, mismo patrón aprendido con Pulse pero aplicado desde el arranque, no como corrección posterior.

## Novedades para el usuario
No aplica — proyecto de uso personal/grupo chico conocido, sin pantalla pública de "qué cambió".

## Despliegue
**En producción.** Repo creado y público, keystore de firma generado, pipeline de release funcionando, datos reales migrados y verificados, actualización automática probada de punta a punta por el usuario.

## Claves secretas
Ninguna — la app no tiene backend ni API keys. El keystore de firma vive solo en `secretos/` (local, gitignored) y en GitHub Actions Secrets.

## Escalabilidad
- Nuevo campo en movimiento: actualizar `Movimiento` en `types.ts`, `normalizarEstadoImportado` en `estado.ts`, y el export CSV en `respaldo.ts`.
- Nueva pantalla: agregar a `src/screens/`, registrarla condicionalmente en `App.tsx` (patrón simple, sin librería de navegación — la app es chica).

## Compatibilidad
